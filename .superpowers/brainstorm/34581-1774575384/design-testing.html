Integrate Stage Design — Section 4: Testing & Error Handling

How we verify each module and what happens when things go wrong.

Test Structure

engine/test/integrate/
  ├── embedding-service.test.ts    // atom→text conversion, batch splitting, cache hits
  ├── entity-resolver.test.ts      // mention extraction, clustering, disambiguation
  ├── relation-detector.test.ts    // pair finding, scoring, classification
  ├── graph-builder.test.ts        // atom finalization, adjacency list, edge types
  ├── integration.test.ts          // full pipeline: integrate() end-to-end
  └── fixtures/
      ├── sample-atoms.ts          // small set of CandidateAtoms from 2-3 "books"
      └── mock-embeddings.ts       // pre-computed embeddings for deterministic tests

Test Strategy Per Module

embedding-service.test.ts

  • atomToText — each frame type produces readable English/Chinese sentence
  • batching — 100 atoms with maxBatchSize=50 produces 2 API calls
  • cache — already-embedded atoms skipped, new atoms embedded
  • cosineSimilarity — known vectors produce expected scores
  • Mock EmbeddingProvider — returns deterministic vectors, no real API calls

entity-resolver.test.ts

  • extractMentions — correct roles extracted per frame type, nothing from non-entity roles
  • exact clustering — "replication lag" and "Replication Lag" merge
  • embedding clustering — similar mentions (cosine ≥ 0.85) merge within domain
  • domain boundary — same text in different domains stays separate
  • incremental — new mention merges into existing entity, not creates duplicate
  • disambiguation — mock LLM returns merge/separate, entities update accordingly
  • cross-domain links — similar entities across domains get linked, not merged

relation-detector.test.ts

  • pair filtering — only atoms sharing entities are compared; same-book pairs excluded
  • reinforcement — two causal atoms with same roles from different books → reinforces
  • contradiction — two atoms with opposing claims about same entity → contradicts
  • extension — definition + has_property on same entity → extends
  • LLM tiebreaker — ambiguous similarity sends to mock LLM, respects response
  • no false positives — unrelated atoms sharing an entity get entity_link only, no relation

graph-builder.test.ts

  • finalize — CandidateAtom promoted to Atom with all new fields populated
  • confidence — reinforcement boosts (+0.05/source), contradictions don't change, caps at 1.0
  • bidirectional edges — A reinforces B → edges on both A and B
  • edge types — correct EdgeType for each relation kind
  • incremental merge — new atoms + edges merged into existing graph without duplicates

integration.test.ts

  • first book — integrate() on empty graph → produces valid KnowledgeGraph
  • second book — incremental integrate finds entities, relations, grows graph
  • batch rebuild — integrating all books sequentially on empty graph = same result as incremental
  • stats — IntegrationStats accurately counts everything

Error Handling

Failure Behavior Rationale
Embedding API fails Retry 2x with backoff. If still fails, abort integration — can't proceed without embeddings. Embeddings are required for all downstream steps.
LLM disambiguation fails Retry 2x. On failure, treat ambiguous clusters as separate (conservative). Log warning. False separation is safer than false merge. Can rerun later.
LLM relation classification fails Retry 2x. On failure, skip the pair — entity_link edge still exists. Log warning. Missing a relation is recoverable. The graph is still connected via entities.
LLM returns unparseable JSON Retry with same prompt (LLM non-determinism often fixes it). After 2 retries, skip batch. Same pattern as Extract stage. Lenient — don't lose the whole run.
Existing graph files corrupt/missing If any file missing or unparseable, treat as empty graph (batch rebuild mode). Log warning. Rebuilding is always safe. Better than crashing on corrupt state.
Atom has no domain tags Assign to "untagged" domain. Entity resolution still works within that bucket. Don't drop atoms. Degrade gracefully.

Design principle: Same as Extract stage — lenient, never lose data. LLM failures degrade to conservative algorithmic defaults. The graph is always buildable from entities alone. Relations are enrichment, not requirements.
