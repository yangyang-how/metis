Integrate Stage Design — Section 3: Module Responsibilities

Each file, what it does, and the algorithm inside.

index.ts — Orchestrator

~80 lines

Exports integrate(input: IntegrateInput): Promise<KnowledgeGraph>. Calls the four sub-steps in order. Handles loading/saving the knowledge graph files. Collects stats. No business logic lives here. 

async function integrate(input): KnowledgeGraph {
  // 1. Embed new atoms
  const embeddings = await embedAtoms(input.atoms, input.embeddingProvider, existing.embeddings)

  // 2. Resolve entities
  const entities = await resolveEntities(input.atoms, existing.entities, embeddings, input.llmProvider)

  // 3. Detect relations
  const relations = await detectRelations(input.atoms, existing.atoms, entities, embeddings, input.llmProvider)

  // 4. Build graph
  return buildGraph(input.atoms, existing, entities, relations, embeddings)
}

embedding-service.ts — Embed & Cache

~120 lines

Converts atoms to embeddable text, calls EmbeddingProvider in batches, caches results.

Key functions

  • atomToText(atom) — concatenates role values into a natural language sentence
  • embedAtoms(atoms, provider, existingCache) — skips already-embedded atoms, batches new ones
  • cosineSimilarity(a, b) — utility for comparing two embeddings

Atom → Text example

// definition atom:

entity-resolver.ts — Entity Resolution

~250 lines

The most complex module. Extracts entity mentions, clusters them, disambiguates with LLM, creates cross-domain links.

extractMentions(atoms) → EntityMention[]

Walks all atoms. From each role value, extracts a mention. Which roles are "entity-bearing" depends on frame type: definition.term, has_property.entity, causal.cause, causal.effect, is_a.instance, is_a.category, threshold.metric, etc. A mapping of frame → entity-bearing roles is defined as config, not hardcoded per-role.

clusterMentions(mentions, embeddings) → MentionCluster[]

Groups within each domain. First pass: exact normalized match. Second pass: embed mention text, merge clusters where centroid similarity ≥ 0.85. Incremental: new mentions are compared against existing entity canonical names + aliases first.

disambiguate(ambiguousClusters, llm) → MergeDecision[]

For clusters with similarity 0.70–0.85: batch them to LLM. Prompt: "Given these mentions in [domain], are they the same concept? Respond: merge / separate / unsure." Batched — up to 20 pairs per LLM call to minimize cost.

linkCrossDomain(entities, embeddings) → CrossDomainLink[]

Compare entity canonical names across domains using embedding similarity. Threshold ≥ 0.75 → create cross_domain_link. No LLM — this is a signal for the Apply pipeline, not a merge decision.

relation-detector.ts — Relation Detection

~200 lines

Compares atoms that share entities. Classifies pairs as reinforcement, contradiction, extension, or unrelated.

findCandidatePairs(newAtoms, existingAtoms, entities) → AtomPair[]

For each new atom, find existing atoms that share at least one entity. Filter out same-book pairs (same source can't reinforce itself). Returns pairs to evaluate.

scoreAndClassify(pairs, embeddings, llm) → Relation[]

For each pair: compute full-atom embedding similarity. Apply classification rules:
• Same frame + similarity ≥ 0.90 → reinforcement (algorithmic)
• Same frame + similarity 0.75–0.90 → LLM tiebreaker
• Same frame + opposing role values → contradiction candidate → LLM confirm
• Different frame + same entity → extension (algorithmic)
• Similarity < 0.75 → skip (entity_link edge still exists)

graph-builder.ts — Graph Construction

~150 lines

Takes all resolved data and produces the final KnowledgeGraph. Pure data transformation — no LLM calls.

finalizeAtoms(candidates, entities, relations) → Atom[]

Promotes CandidateAtom → Atom. Populates entityRefs from entity index. Populates reinforcedBy, contradictedBy, extendedBy from relations. Updates confidence: +0.05 per reinforcement source (capped at 1.0).

buildAdjacencyList(atoms, entities, relations) → GraphIndex

Creates edges: entity_link for atoms sharing entities, reinforces / contradicts / extends from detected relations, cross_domain from entity cross-domain links. All edges are bidirectional (A→B and B→A both stored).

prompts.ts — LLM Prompts

~100 lines

Two prompt templates, both designed for cheap models (Haiku tier):

Entity Disambiguation

"Given these entity mentions in [domain], are they the same concept? For each pair, respond: merge / separate / unsure." Batched — up to 20 pairs per call.

Relation Classification

"Given these two atoms about [entity], classify the relationship: reinforce (same claim), contradict (opposing claims), extend (adds nuance), or unrelated." Batched — up to 10 pairs per call.
