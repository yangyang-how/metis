Integrate Stage Design — Section 1: Data Flow

The complete flow from Extract output to finalized knowledge graph.

INPUT

CandidateAtom[] from Extract
+ existing KnowledgeGraph (if incremental)

→

Incremental mode: new atoms compared against existing graph
Batch mode: integrate() called per-book on empty graph → same code path

① Embed

embedding-service.ts

Embed all new atoms (concatenate role values → natural language sentence → OpenAI embed). Cache embeddings to avoid re-embedding on rebuild. Output: Map<atomId, float[3072]>

② Resolve Entities

entity-resolver.ts

Extract entity mentions from roles → normalize → cluster within domain (embedding similarity ≥0.85) → LLM disambiguate ambiguous clusters (0.70–0.85) → assign canonical names → create cross-domain links (≥0.75). Output: EntityIndex (entities with atomId refs + cross-domain links)

③ Detect Relations

relation-detector.ts

For atoms sharing entities: compute frame-aware similarity → classify as reinforcement (≥0.90), contradiction (opposite roles), extension (different frame, same entity), or unrelated. Ambiguous pairs (0.75–0.90) go to LLM. Output: Relation[] (type + atom pair + confidence)

④ Build Graph

graph-builder.ts

Finalize atoms (add entityRefs, reinforcedBy, contradictedBy, extendedBy, update confidence). Build adjacency list from entity links + detected relations. Output: Atom[] (finalized) + GraphIndex (adjacency list) + VectorIndex (embeddings)

OUTPUT — KnowledgeGraph

4 JSON files written to disk

atoms.json entities.json graph.json embeddings.json

Incremental behavior: When integrating a new book, the existing atoms.json, entities.json, graph.json, and embeddings.json are loaded first. New atoms are embedded, resolved against existing entities, compared against existing atoms for relations, and then all four files are updated. Entity resolution merges new mentions into existing clusters. The graph grows incrementally — no full rebuild needed.
