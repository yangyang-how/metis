Relation Detection: Reinforcement, Contradiction, Extension

After entity resolution, how do we find atoms that interact?

The challenge: 4,101 atoms. Comparing every pair = ~8.4M comparisons. Most pairs are irrelevant (a nutrition atom will never reinforce a distributed systems atom). We need a fast filtering pass before any expensive comparison.

Detection Pipeline

1

Filter: Same Entity Cluster

Only compare atoms that share at least one resolved entity. If atom A talks about "replication lag" and atom B talks about "nutrition timing," skip. This cuts 8.4M pairs down to maybe ~10K-50K.

2

Score: Frame-Aware Similarity

For each candidate pair, compute a similarity score that accounts for:

  • Same frame type? — causal vs causal is a strong signal for reinforcement/contradiction
  • Role value similarity — embed and compare corresponding roles (cause↔cause, effect↔effect)
  • Different source? — same book can't reinforce itself (that's just redundancy)
3

Classify: Algorithmic + LLM Tiebreaker

Similarity ≥ 0.90 → Reinforcement (auto-classify, no LLM)
Similarity 0.75–0.90 → Ambiguous — send to LLM: "reinforce, contradict, extend, or unrelated?"
Same frame, opposite roles → Contradiction candidate — send to LLM to confirm
Same entity, different frame → Extension candidate — different angle on same concept
Similarity < 0.75 → Skip (entity_link edge exists from shared entity, but no semantic relation)
4

Apply: Update Atoms + Build Edges

Reinforcement: boost confidence on both atoms (+0.05 per reinforcing source, capped at 1.0). Add reinforcedBy refs. Create reinforces edge.
Contradiction: keep both atoms unchanged. Add contradictedBy refs. Create contradicts edge. Flag for Apply pipeline.
Extension: add extendedBy ref on the base atom. Create extends edge.

The key insight: entity resolution does the heavy filtering. Relation detection only looks at atoms that share entities.
