Entity Resolution Pipeline

How do we go from 4,101 atoms to a resolved entity index?

Step 1: Extract Mentions

Pull entity candidates from atom roles. definition.term, has_property.entity, is_a.instance, causal.cause, causal.effect, etc. Each mention = (text, atomId, domain, role).

~8K-12K mentions from 4,101 atoms

→

Step 2: Cluster Algorithmically

Group mentions by exact match + normalized form (lowercase, trim, remove articles). Within each domain, embed mentions and cluster by cosine similarity (threshold ~0.85).

No LLM needed. Fast pass.

→

Step 3: LLM Disambiguation

For ambiguous clusters (similarity 0.70–0.85), batch them to a cheap LLM: "Are these the same concept in this domain?" Returns merge/separate/unsure.

~50-200 LLM calls (batched)

→

Step 4: Cross-Domain Linking

Compare entity canonical names across domains using embedding similarity. Above threshold (0.75) → create cross_domain_link. No merge, just a signal.

Pure embedding math. No LLM.

The Embedding Question

Where do we get embeddings? This affects cost and quality.

A

Local Embeddings (transformers.js / Ollama)

Run a small embedding model locally (e.g., nomic-embed-text via Ollama, or all-MiniLM-L6-v2 via transformers.js). Free, fast, no API dependency. Quality is ~90% of cloud models for English; weaker for Chinese.

Pros

  • Zero cost
  • No API key needed
  • Works offline

Cons

  • Weaker Chinese support
  • Requires local model download (~400MB)
  • Slightly lower quality
B

Cloud Embeddings (OpenAI / Voyage)

Use OpenAI's text-embedding-3-small or Voyage AI's bilingual model. Best quality, especially for Chinese-English cross-lingual. ~$0.01 per 1M tokens.

Pros

  • Best bilingual quality
  • Trivially cheap ($0.02 for our whole corpus)
  • Proven at scale

Cons

  • Requires API key
  • Online dependency
  • Another provider to configure
C

Provider-Agnostic (same abstraction as LLM calls)

Add an EmbeddingProvider interface to engine/src/llm/ — same pattern as LLMProvider. Ship with OpenAI adapter first. Users can swap in local models later. Config via --embedding-provider.

Pros

  • Consistent with existing architecture
  • Users choose based on their setup
  • Local + cloud both supported

Cons

  • More code to write up front
  • Still need at least one concrete adapter to ship

Shannon's recommendation: C with OpenAI adapter first. Follows the existing provider pattern. Bilingual support matters — half your books are Chinese. And $0.02 to embed the whole corpus is not worth agonizing over.
